# Delivery Checklist

Use this before sending a workflow audit to a client.

## Scope

- [ ] One workflow is named clearly.
- [ ] The trigger is documented.
- [ ] The output is documented.
- [ ] Owners and tools are listed.
- [ ] Out-of-scope workflows are named.

## Evidence

- [ ] Intake notes are reflected accurately.
- [ ] Screenshots or examples are referenced without exposing private data.
- [ ] Missing information is called out instead of guessed.
- [ ] Sensitive data is excluded from the public or shareable version.

## Recommendations

- [ ] Three opportunities are ranked.
- [ ] The top recommendation has a trigger, inputs, outputs, review points, and failure handling.
- [ ] The recommendation is small enough for a first sprint.
- [ ] The report says what should not be automated yet.

## Business Value

- [ ] Time waste is estimated.
- [ ] Risk is described plainly.
- [ ] Implementation effort is realistic.
- [ ] Next step is obvious.

## Acceptance

- [ ] The client can tell whether the build worked.
- [ ] Failure cases are documented.
- [ ] Human approval points are preserved.
- [ ] Rollback or disable behavior is described.

## Handoff

- [ ] Report is delivered as Markdown, PDF, or client-ready document.
- [ ] Follow-up proposal is attached or summarized.
- [ ] Implementation scope is separate from the audit.
- [ ] Payment or invoice status is recorded.
